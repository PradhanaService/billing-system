How it was tested

Each module was built and tested before the next one started. The whole suite ran again after every module, so a later change could not quietly break an earlier screen.

Unit testsBusiness rules in the services: money in paise, ledger postings, numbering, permissions. Named by requirement ID where a rule has one.
Screen testsEach page rendered with bUnit on a real database. Pop-ups, drop-downs and buttons are clicked the way a user would.
Integration testsAll modules together through the real services, and the whole app over real HTTP with login cookies and PDF downloads.
Browser runA fresh install driven in Chromium, from the first Admin sign-in to a restore, through the real screens.

Business rules that differ from the written spec

These follow the finalized design and the client’s instructions. Each one changes a rule in CLAUDE.md or the spec PDFs, so it needs the client’s written agreement before handover.

  1. Receipts are matched to invoices the user ticks.
    The spec gives automatic oldest-first matching in Version 1.0 and lists hand matching as Version 1.1. A receipt with nothing pending is still kept on account as an advance.
  2. Reference No. is removed from receipts and payments.
    The spec makes it required for Bank and UPI.
  3. Receipt and payment numbers show as plain numbers (4, not RV-4).
    They are still stored with their prefix, so every voucher number stays unique.
  4. Invoice Edit cancels the original and issues a corrected copy with a new number.
    Only capacity, rate, and In/Out time can change. The ledger is never edited: the original is reversed, and any receipt already matched moves to the copy.
  5. The Reports screen shows only the Vehicle Trip Report.
    Daily Sales, Supplier-wise Outstanding, Trial Balance and Cash Book still exist in the code and pass their tests, but are no longer on screen. The spec lists them as Should have.
  6. Ledger Statement and Customer Master screens are removed, and Bill To customer is removed from the Sales Invoice.
    The services behind them are kept and tested, so they can return without rework.
  7. Password Management replaces Users & Roles.
    The Admin sets a password directly, with no temporary password or forced change. If the Sales login has not been made yet, setting its password creates it.
  8. Restore database and Delete all data were added.
    Both are Admin only, take a safety backup first and are recorded in the Activity Log. Delete all data needs the Admin password and the words DELETE ALL DATA. It keeps the two logins and the backup files.
  9. The backup folder is typed in, not picked from a folder window.
    A web page cannot browse folders on the computer. The app checks it can write to the folder before saving the choice.
  10. “Created by” stays on the Sales Invoice for the Sales login, although the design does not show it.
    The client rule from November 2026 requires a name on every invoice made on the shared login.

Not covered by this run

  • The Windows installer was not rebuilt, and the app was not checked on a second computer or a clean Windows install. CLAUDE.md asks for that once a week.
  • Browser tests ran on Linux in Chromium only.
  • The browser script is run by hand. It is not part of dotnet test.
  • An invoice saved after 6:00 PM carries the next date, as the 6 PM to 6 PM business-day rule says. Staff should be told so this does not look like a mistake.
